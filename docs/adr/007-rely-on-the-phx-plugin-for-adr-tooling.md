# 007: Rely on the phx Plugin for ADR Tooling

## Context

[ADR 004][] replaced ADR frontmatter's `tags` with `scope` and ported a generator from
`todofixthis/phx-claude-siat` to validate it: `scripts/adr/generate_index.py`, parsing
frontmatter with PyYAML. An `adr_index` autohooks pre-commit hook ran it whenever a commit
staged an ADR, regenerating and staging the index and blocking the commit on any fault,
and an `adr-index` CI job regenerated the index and failed on a diff.

[`phx:writing-adrs`][] now ships its own stdlib tool, [`adr.py`][], beside the skill. It
indexes, validates, scaffolds, supersedes, discharges and renumbers ADRs, and answers
which decisions bind a path. The phx plugin's hooks call it in Claude Code sessions:
they inject the decisions binding a file the first time a session touches it,
regenerate the index after a file-tool edit to an ADR, and report faults. They report
only; none blocks. The tool also installs as a `phx-adr` command, so CI can run it.

The two cannot run side by side. Both write `docs/adr/INDEX.md`, and their output
differs only in the header line, but that line decides everything: the plugin's hooks
stay silent unless it names `phx:writing-adrs`, and the repo generator's CI job fails
unless it names the generator. A session that let `adr.py` write the index (`ca29de1`)
was reverted minutes later (`7e39b97`) to get CI green, switching the hooks back off.

The maintainer has made the phx plugin canonical for ADR tooling, and
[`.claude/settings.json`][] enables it for Claude Code sessions in this repository.
Every ADR here so far was committed with a Claude co-author.

## Options

Options 2, 3 and 4 all drop the repo generator for `adr.py`'s index format, and so share
the migration; it does not rank them.

### Option 1: Do nothing

**Pros:** The pre-commit hook blocks a faulty commit for every committer.
**Cons:** The phx plugin's hooks stay off, and `adr.py` can't be used here without
fighting the repo generator over the index. The repo generator is a port that has to be
kept in step with the skill by hand, as ADR 004's Consequences already anticipated.

### Option 2: The plugin's tool in sessions and in CI (Accepted)

Delete the repo tooling. Sessions get the plugin's hooks; a CI job runs `phx-adr check`
from the plugin at a pinned release's commit.

**Cons:** No local check blocks a commit; a fault from outside Claude Code is caught
only once pushed. Outside Claude Code nothing allocates a number or regenerates the
index, so the author runs `phx-adr` by hand. The pinned ref has to be bumped by hand.
**Risks:** Sessions load whatever plugin release is installed, not the pinned one. A
release that changes the index format leaves CI reporting the index stale right after
a session regenerates it, until the pin catches up.

### Option 3: The plugin's hooks alone

**Pros:** Nothing to pin.
**Cons:** Nothing outside a Claude Code session with the plugin checks the corpus, and
the hooks only report, so a fault from any other commit lands unnoticed. A commit that
rewrites the index's header line turns the hooks off without a report.

### Option 4: Keep a repo-local tool in step with the plugin

Change the repo generator's header to the plugin's, or vendor `adr.py` in its place.

**Pros:** A pre-commit hook could keep blocking faulty commits, plugin or not.
**Cons:** A copy that drifts from the plugin, the maintenance cost Options 2 and 3
remove: the header is only the first divergence a plugin release can introduce.

## Decision

Option 2. It keeps one implementation of the conventions, maintained with the skill
that states them, and keeps the CI backstop the `adr-index` job gave. Option 3 would
make ADRs the one check here that a commit made outside Claude Code skips entirely.

ADR frontmatter keeps ADR 004's convention, now owned by the skill rather than restated
here: `scope` names the paths a decision binds, never `tags`.

## Consequences

- `docs/adr/INDEX.md` is generated by `adr.py` in the skill's format, which switches the
  plugin's hooks on here.
- `scripts/`, the generator's tests, the `adr_index` hook, and PyYAML and its type stubs
  (the generator was their only user) are removed; the `adr-index` CI job becomes `adrs`.
- The CI `adrs` job and `AGENTS.md`'s `phx-adr` commands pin a plugin release's
  commit. `.claude/settings.json` pins no version, so sessions move on their own; bump
  both when `adrs` disagrees with what a session wrote, and fix whatever the new
  release reports in the same change.
- Neither `adrs` nor the `adr-index` job before it is a required status check on
  `develop` or `main`, so a red run shows on a pull request but does not block its
  merge until a maintainer adds it to the required checks.
- ADR 004's choice of PyYAML over the skill's stdlib parser is reversed: frontmatter
  values must now meet the skill's one-line rules, which the corpus already does.
- The plugin is Claude Code's, so an agent in another harness gets no session hooks,
  and meets the conventions only through `AGENTS.md`, the skill and CI.
